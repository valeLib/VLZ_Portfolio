Overview

Pawstchi is a hybrid casual mobile game for iOS and Android built as an academic UX project at Universidad Europea de Madrid. Two systems are woven together: a match-3 puzzle mechanic where players complete paw-print grid levels, and a virtual pet system where those puzzle completions fund the care, evolution, and customization of a pixel art robot cat the player names themselves.

The academic thesis underneath the design: pixel art retro aesthetics with a pastel palette are a UX tool, not just a style choice. They activate nostalgia, reduce cognitive load through familiar visual grammars, and create the conditions for emotional attachment — all of which serve retention in a hybrid casual game.

Core Game Loop

The engagement model is a deliberate cycle between two distinct emotional registers:

Play puzzle level
  → earn hearts & gems
  → return to Home screen
  → care for / evolve / customize Pawstchi
  → emotional attachment deepens
  → motivation to play next level

The match-3 puzzle uses a 6×6 grid of paw-print tiles with a move counter, not a timer. This is a deliberate stress-reduction and accessibility decision: removing time pressure keeps the experience in the cozy-casual register and eliminates the primary anxiety trigger in competitive puzzle games.

UX Framework: Self-Determination Theory

Pawstchi's design maps explicitly to the three core psychological needs identified by Ryan, Rigby & Przybylski (2006) in their SDT-based model of video game motivation:

Autonomy — No energy systems, no timers, no forced rest windows. Every session is player-initiated. Monetization is optional and transparent. The player controls the pace entirely.

Competence — Move-limited puzzles let the player define their own success metric. The dual MOVES + SCORE display accommodates efficiency-focused and score-chasing player types simultaneously. Difficulty scales so achievable goals always exist.

Relatedness — The naming ritual at onboarding is the single most powerful design decision in the game. A player who has named their cat before playing a single level has already formed an attachment. Visible emotional states on the sprite create the perception of a responsive relationship.

Emotional Attachment Architecture

Four layered mechanisms work together to build and sustain attachment to the virtual pet:

  1. Naming during onboarding — The system asks for a name, the player provides it, a confirmation modal echoes it back: “Is your Pawstchi called Moka?” This loop creates personal investment before any gameplay. The strongest attachment generator in the design.

  2. Visual variant as identity — The Ragdoll vs. Tabby choice at onboarding mirrors Meow-Chi collectible psychology: the player isn’t just picking an aesthetic, they’re declaring a preference. The pet becomes a self-expression object.

  3. Care cycle without punishment — The hearts bar depletes over time but never triggers a pet-death state (Tamagotchi’s penalty). Pawstchi uses positive reinforcement (full hearts → visible happiness) rather than negative (neglect → death). Lower stakes, longer retention.

  4. Evolution as milestone — Bebé → Adolescente → Adulto is a discrete, anticipated event. Each evolution is a first. These moments are retention anchors.

Visual Identity

The color palette sits in the pastel-retro register without reading as childish:

Typography uses Goldmant (kawaii-retro display font) for primary elements and a pixel bitmap font (Press Start 2P register) for HUD counters. The pixel art coherence rule applies throughout: every UI element — icons, sliders, checkboxes, buttons — is rendered in pixel art style. Mixing pixel sprites with smooth vector UI elements creates cognitive dissonance. Consistency of visual grammar is an interface principle.

Sprite resolution is deliberately ~64–96px scaled (Game Boy Color register) — between the 16×16 Tamagotchi grid and modern high-resolution assets. This is a conscious positioning decision, not a technical limitation.

Interface Architecture (11 Screens)

Navigation philosophy: All secondary flows resolve in a maximum of 2 steps from Home. Every secondary screen includes a pixel art Home button. The pet is always one tap away.

Accessibility (WCAG 2.1 AA): 4.5:1 color contrast minimum, 44×44dp touch targets, granular per-category notification controls, separate Music and SFX sliders.

Monetization Model

Design principle: all monetization is optional, transparent, and non-coercive. No loot boxes. No pay-to-win. No energy systems.

Hearts are also earned through gameplay. The €4.99 tier is positioned as "support the game" rather than a feature unlock — consistent with ethical F2P design.

  • Hybrid casual dominates the top 100 App Store Spain in 2024

Competitive gap identified: No existing title in the Spanish App Store virtual pet category combines match-3 + pixel art robot cat + player-assigned name + pastel-retro identity + isometric home + non-coercive ad monetization simultaneously.
